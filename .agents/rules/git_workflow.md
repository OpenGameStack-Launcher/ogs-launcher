# Git Workflow Rules

When working on this repository, you MUST follow these Git workflow rules to prevent merge conflicts and ensure clean commits:

1. **Use Git Worktrees**:
   - Instead of checking out branches directly in the main repository directory, **ALWAYS** use Git worktrees for your tasks.
   - We will store worktrees in `c:\Projects\ogs-frozen-stacks` or a dedicated `.worktrees` folder, but since the user has multiple workspaces, wait, the user's workspaces are:
     `c:\Projects\OpenGameStack-Launcher.github.io`
     `c:\Projects\ogs-frozen-stacks`
     `c:\Projects\ogs-launcher`
   - It is best to create worktrees inside a dedicated directory, for example `c:\Projects\ogs-launcher\.worktrees\<branch_name>`.
   - Command: `git worktree add .worktrees/<branch-name> -b <branch-name>`
   - Run all your commands (tests, builds, commits) inside that worktree directory.
   - When the PR is merged, you can clean up the worktree using `git worktree remove .worktrees/<branch-name>`.

2. **Clean Working Tree Check**:
   - After running `git commit` and BEFORE pushing or creating a Pull Request, you **MUST** run `git status`.
   - Ensure there are **no modified files** and **no untracked files** (like `.uid` files generated by Godot) remaining in the change list.
   - If `git status` shows uncommitted changes, you must `git add` and `git commit` them before proceeding.
