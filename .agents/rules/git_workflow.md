# Git Workflow Rules

When working on this repository, you MUST follow these Git workflow rules to prevent merge conflicts and ensure clean commits:

1. **Use Git Worktrees**:
   - Instead of checking out branches directly in the main repository directory, **ALWAYS** use Git worktrees for your tasks.
   - It is best to create worktrees inside a dedicated directory, for example `c:\Projects\ogs-launcher\.worktrees\<branch_name>`.
   - First, ensure you have the latest remote changes: `git fetch origin`
   - Command: `git worktree add .worktrees/<branch-name> -b <branch-name> origin/main` (This ensures your new branch is based on the absolute latest main, avoiding the need to pull main locally first).
   - Run all your commands (tests, builds, commits) inside that worktree directory.

2. **Clean Working Tree Check**:
   - After running `git commit` and BEFORE pushing or creating a Pull Request, you **MUST** run `git status`.
   - Ensure there are **no modified files** and **no untracked files** (like `.uid` files generated by Godot) remaining in the change list.
   - If `git status` shows uncommitted changes, you must `git add` and `git commit` them before proceeding.

3. **Worktree Cleanup**:
   - Worktrees are temporary environments and should not be left lingering.
   - Once a PR has been merged, OR once you are explicitly done with a task/issue and moving on to the next one, you **MUST** immediately clean up the worktree you were using.
   - Run `git worktree remove .worktrees/<branch-name>` (or `git worktree remove --force .worktrees/<branch-name>` if there are unmerged changes you are explicitly discarding).
   - This ensures the workspace stays clean and we don't accumulate dozens of old worktrees.
